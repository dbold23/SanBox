# LabRAG design decisions (September 2026)

Why LabRAG looks the way it does. The problems it answers are catalogued in
[2026-09-shark-rag-v1-assessment.md](2026-09-shark-rag-v1-assessment.md).

## Goal

Lab members should not install anything. One machine indexes the lab's papers and serves a
web page; papers stay where they already live (NAS share, Google Drive). Answers cite paper
and page and can be checked in one click.

## Decisions

| Decision | Why | Alternative rejected |
|---|---|---|
| One SQLite file for documents, passages, FTS5 keyword index and float32 vectors | Zero services, copyable, ~1 GB for a few thousand papers, readable by any Python. `PRAGMA journal_mode=DELETE` (no WAL) so it also works on a network share with one writer | LanceDB + SQLite (v1): two stores that drifted apart, WAL unsafe on SMB |
| Brute-force cosine over an in-memory matrix, refreshed when `index_version` changes | 50k passages x 384 dims is 75 MB and a query is ~10 ms; nothing to tune | sqlite-vec / FAISS / a vector DB: another moving part for a corpus this size |
| Hybrid retrieval: FTS5 BM25 + vectors fused with Reciprocal Rank Fusion, at most 3 passages per paper | Exact terms (tag models, species names, place names) matter in this domain and embeddings miss them; RRF needs no score calibration | Vector-only (v1); a reranker model (another download, marginal gain at k=8) |
| ~300-word passages, 50-word overlap, page numbers kept, reference lists cut at the heading | Big enough for an idea, small enough for 8 in a prompt; 40% overlap in v1 doubled the index and duplicated hits | Token-based splitting with LlamaIndex |
| Content hash identity; size+mtime as the cheap first check; forget deleted files; never delete when a source folder is empty | Renames and Drive re-syncs must not duplicate; an unmounted NAS must not wipe the index | path+mtime ledger (v1) |
| Title/authors/year from Crossref by DOI, else PDF metadata, else `Author_Year_Title.pdf` filename | Deterministic, checkable citations like `Jorgensen 2010, p. 4` | Asking the model to format citations; most-frequent-year heuristic (v1) |
| Google Drive read through the Drive API into a local mirror, or via Drive for Desktop as a plain folder | The mirror makes Drive just another folder for the indexer, and works on a Linux host; Docs export as text | Indexing Drive placeholders in streaming mode (slow, flaky) |
| Local embeddings by default (fastembed, bge-small) | No account, no GPU, no Ollama install; ~130 MB once | Ollama required (v1); API embeddings (needs a second key since Anthropic has none) |
| Answers from Claude when a key is set, else Ollama if running, else search-only | One key on the server is the simplest good setup; search-only keeps the tool useful with nothing configured | A settings UI with 5 x 3 providers (v1) |
| Numbered `[n]` citations, rendered as links to the source list and to the PDF at that page | 1:1 mapping the reader can verify | Author-year strings generated by the model |
| No settings in the web page, optional shared password, everything else in one env file written by `labrag init` | Lab members cannot break it; keys never reach the browser | Settings tab persisting keys in SQLite (v1) |
| Dropped: paper acquisition crawler, markdown importer, summary tab, reading status/notes, MCP server | Personal research-program tooling, dead code, or single-user state on a shared server. Any of it can come back as a separate script | |

## Known limits

- One writer per index. The web page's "Update index" and `labrag index --every` on the same
  machine share one settings file, so use one or the other.
- Scanned PDFs need OCR first; LabRAG lists them rather than guessing.
- Absolute paths are stored per machine. A shared index on the NAS serves files correctly only
  from the machine that indexed them; citations still display fine everywhere.
- No per-user history. The page keeps the last three exchanges in the browser only.
